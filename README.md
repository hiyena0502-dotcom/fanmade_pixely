# PIXELY : LOST SKY

잠뜰님의 생일을 준비하다 여러 이야기의 세계를 여행하게 되는 비공식 팬메이드 코미디 어드벤처입니다. 현재는 챕터 1 도입 장면과 파티방 조사 화면, 미션·인벤토리, 컬렉션, 꿈뜰이 옷장, 저장 관리가 구현되어 있습니다.

## 실행

정적 사이트입니다. `index.html`을 열거나 로컬 정적 서버에서 실행할 수 있습니다. 별도 빌드와 외부 패키지는 필요하지 않습니다.

## 현재 구조

- **HOME** — 새 이야기, 이어하기, 세이브 슬롯 관리
- **CHAPTER 1** — 새 이야기에서 집 전경의 문을 클릭하면 문 클로즈업으로 바뀝니다. 이어서 실내 파티방 위에 챕터 제목이 나타나며 조사 화면으로 이어집니다.
- **CHAPTERS** — 챕터 진행 기록
- **COLLECTION** — 인물 카드, 아이템, 엽서 다이어리
- **WARDROBE** — 홈 오른쪽 위의 별도 버튼으로 여는 밝은 꾸미기 화면. 브라우저에서 직접 베이스/옷/소품/얼굴/장식 이미지를 추가할 수 있고, 네 분류 모두 여러 레이어를 동시에 선택할 수 있습니다. 각 이미지의 좌우·위아래·크기·회전과 레이어 순서도 조정할 수 있습니다.

기존 세이브는 그대로 읽습니다. 이미 인트로를 마친 세이브는 이어하기에서 도입 장면을 다시 재생하지 않습니다.

## 파일

- `index.html` — 화면 구조
- `style.css` — 화면 스타일과 반응형 레이아웃
- `data/game-config.js` — 카드·아이템·챕터·옷장 분류·스토리 기본 데이터
- `data/editor-schema.js` — DEV EDITOR 입력 필드와 상호작용 스키마
- `app.js` — 저장, 화면 렌더링, 챕터 진행, 컬렉션, 옷장, DEV EDITOR 동작
- `site-version.json` — 배포된 사이트 버전

세이브는 브라우저 `localStorage`의 `pixely-lost-sky-saves-v2` 키에 슬롯 세 개로 저장됩니다. 브라우저 데이터를 지우면 세이브도 삭제됩니다.

컬렉션의 카드 목록은 잠뜰 멤버·상황극 인물·요정·기타로 분류됩니다. 앞으로 카드 항목에 `world` 문자열을 추가하면 해당 작품 필터도 자동으로 나타납니다. 아직 작품별 캐릭터 데이터는 입력하지 않았습니다. 아이템은 중요 물건·기념품·선물·꾸미기·미확인으로 나뉩니다. 엽서는 기존 한 목록을 유지합니다.

새 게임의 인벤토리는 비어 있습니다. 기존 봉제인형을 획득하면 옷장에서 소품으로 장착할 수 있습니다. 추후 `catalogue.items`에 `wardrobeSlot`(`outfit`, `accessory`, `face`, `decoration`)이 지정된 아이템을 추가하고 스토리에서 `window.PixelyInventory.grantItem(itemId)`로 지급하면 선택 항목이 늘어납니다. 옷·소품·얼굴·장식은 모두 `outfit.layers`의 복수 레이어로 저장됩니다. 예전 단일 `outfit/accessory/face/headwear` 세이브는 불러올 때 새 레이어 배열로 변환해 호환합니다. 이미지 소재가 들어온 뒤 대화 화면은 `window.PixelyAvatar.outfitForActiveSave()`에서 장착 상태를 읽어 사용자 이미지에 적용할 수 있습니다.

## 배포할 때

사이트 파일을 수정하면 `app.js`의 `SITE_VERSION`, `site-version.json`의 `version`, `index.html`의 CSS/JS `?v=` 값을 같은 새 값으로 올려 주세요. 열린 탭은 배포 버전이 달라지면 새로고침 안내를 표시합니다. `node --test tests/*.test.js`로 주요 동작과 버전 일치를 확인할 수 있습니다.

### 옷장 이미지 편집

옷장 하단의 **이미지 추가 · 위치 조정**에서 투명 PNG/WEBP/JPG를 직접 등록할 수 있습니다. 베이스 이미지는 별도 업로드하며, 현재 열어 둔 옷 / 소품 / 얼굴 / 장식 탭에 새 파츠 이미지를 추가합니다. 등록한 이미지는 브라우저 IndexedDB의 `pixely-dev-data-v1` 저장소에 보관되고, 좌우(X)·위아래(Y)·크기·회전 값을 이미지별로 기억합니다. 장식 이미지는 여러 개를 동시에 선택해 겹칠 수 있습니다. 이미지는 등록 시 크기를 검사하고 가능한 경우 최적화합니다.


> 옷장 이미지 업로드/위치 조정 UI는 개발자 세팅용 임시 도구입니다. 최종 베이스·파츠 이미지와 위치가 확정되면 해당 설정을 기본 에셋/기본 transform으로 코드에 고정하고, 업로드·위치 조정 UI는 제거할 예정입니다.


### 옷장 레이어 구조 v22

옷·소품·얼굴·장식은 모두 복수 선택 가능한 레이어입니다. 얼굴은 눈/입/눈썹/볼, 의상은 상의/하의/겉옷/신발처럼 세부 파츠를 나눠 등록할 수 있습니다. 소품은 캐릭터가 들거나 착용하는 물건, 장식은 캐릭터 주변의 이펙트·스티커·꾸밈 요소로 구분합니다. 개발자 편집기에서 적용된 파츠의 좌우·위아래·크기·회전뿐 아니라 레이어 순서(맨 아래/한 칸 아래/한 칸 위/맨 위)도 조정할 수 있습니다.


### 개발자 설정실

홈의 **개발자 설정 / DEV SETTINGS** 버튼에서 브라우저 안에서 콘텐츠 데이터를 편집할 수 있습니다.

- **챕터**: ID, 번호, 라벨, 제목, 설명
- **컬렉션**: 카드와 엽서의 이름, 분류, 심볼, 색상, 설명, 세계/메모/캡션
- **아이템**: 이름, TYPE, 심볼, 색상, 설명, 옷장 분류/세부 파츠

챕터에서는 기본 정보와 장면 목록을 편집하고 **장면 열기 · 상호작용 배치**로 실제 게임 화면에 들어갑니다. 그 화면에서 `+ 상호작용 추가` 후 클릭 영역을 직접 배치·이동·크기 조절하고, 조사·대화·획득·이동·아이템 사용·선택지 타입과 실행 문장, 조건, 보상, 다음 연결을 설정합니다.

개발 설정은 IndexedDB에 저장되며 플레이 세이브(localStorage)와 분리됩니다. 기존 localStorage 개발 데이터는 처음 열 때 자동으로 이전합니다. 편집 내용은 초안에 모이고 **모두 저장**을 누르면 검사와 직전 상태 백업을 거쳐 플레이 데이터에 적용됩니다. 챕터 상호작용은 `window.PixelyDevContent.interactionsForChapter(chapterId)`로 읽을 수 있어 이후 실제 챕터 화면의 클릭 포인트와 연결할 수 있습니다. 최종 데이터 확정 뒤 이 개발 설정값을 코드 기본값으로 고정할 수 있습니다.

옷장 개발 도구는 v24부터 **파일 선택 → 등록하고 켜기**의 명시적인 2단계 등록 방식으로 바뀌며, 브라우저 저장 공간 사용량을 표시하고 큰 이미지는 가능한 경우 자동 최적화합니다.


### 챕터 상호작용 배치 v30

상호작용 편집은 개발자 설정실에서 좌표만 입력하는 방식이 아닙니다. 개발자 설정의 챕터에서 **챕터 화면에서 상호작용 배치**를 누르거나, 실제 챕터 플레이 화면의 **EDIT** 버튼으로 장면 편집 모드에 들어갑니다. **+ 상호작용 추가**를 누른 뒤 실제 배경에서 원하는 위치를 클릭해 상호작용 박스를 만들고, 박스를 드래그해 이동하거나 오른쪽 아래 핸들을 끌어 크기를 조정합니다. 세부 대사·조건·보상·다음 장면 등은 같은 챕터 화면의 인스펙터에서 편집합니다.


### 통합 DEV EDITOR · v44

- 상단에서 저장 상태, UNDO/REDO, CHECK, 모두 저장을 사용합니다. 초안은 새로고침하면 사라질 수 있으므로 작업을 마칠 때 모두 저장하거나 JSON으로 내보내세요.
- CHAPTER에는 장면 목록과 배경 이미지 업로드가 있습니다. 기본 챕터 1의 집 밖·문 앞·집 안을 각각 실제 화면에서 열고 상호작용을 배치합니다. 새 장면도 추가할 수 있습니다.
- COLLECTION/ITEM은 목록에서 항목 하나를 선택해 수정합니다. WARDROBE는 기존 이미지·레이어 편집 도구가 통합 에디터 안에 표시됩니다. 에디터 안에서 편집한 베이스와 파츠는 초안에 쌓이고 **모두 저장** 때 IndexedDB에 적용됩니다. 홈의 플레이어 옷장은 그대로 사용할 수 있습니다.
- DATA에서 오류를 검사하고, 개발 데이터와 옷장 이미지를 JSON으로 내보내거나 초안으로 가져오고, 직전 저장 전 상태를 복구합니다. CHECK는 중복 ID, 없는 보상 아이템, 없는 장면/연결, 화면 밖의 클릭 영역을 찾습니다. 오류를 누르면 해당 편집 화면으로 이동합니다.
- 플레이 세이브는 기존 슬롯 구조와 별도로 유지됩니다. IndexedDB를 사용할 수 없는 환경에서는 이전 localStorage 저장을 사용합니다.


### 코드 정리 · v45

정적 콘텐츠와 에디터 스키마를 거대한 `app.js`에서 분리했습니다. `data/game-config.js`는 게임 기본 데이터만, `data/editor-schema.js`는 개발자 편집기의 입력 구조만 담당하고 `app.js`는 상태·저장·렌더링·이벤트 처리에 집중합니다. 기존 세이브/IndexedDB 키와 화면 동작은 바꾸지 않습니다.
